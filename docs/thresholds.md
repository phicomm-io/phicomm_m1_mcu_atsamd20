# 甲醛与 PM 两档阈值

主控沿用原厂 `0x05/0x06` 的写入格式，设置后同时控制绿/黄/红灯色与红档蜂鸣器告警。两种传感器独立配置，默认值仍为甲醛 `100/300`、PM `75/150`。

这是开源扩展的实际效果：原厂写入与 RAM 标志已由指令确认，但原厂显示函数仍比较固定立即数，不能把可配置灯色称为已复现的原厂效果。新实现只沿用其写入格式，增加阈值消费者和明确的读取接口。

## 数值与生效规则

| 测量值 | 灯色 | 蜂鸣器 |
| --- | --- | --- |
| `value <= low` | 绿 | 不新增污染物告警 |
| `low < value <= high` | 黄 | 不新增污染物告警 |
| `value > high` | 红 | 健康数据首次进入告警时，触发原有的有限鸣叫序列 |

参数为无符号 16 位内部整数，要求 `0 <= low <= high <= 65535`。两档相等时黄色区间为空；`0/0` 表示仅零值为绿、正值为红，**不是关闭告警**。反序参数拒绝，两个旧值均保留。原厂允许反序值，但没有为其确认可用的灯色语义，因此开源实现增加校验。

比较使用未为屏幕位数截断的原始甲醛整数和预热/突升处理后的 PM 整数，不做另一次单位换算。不能仅凭该设置接口宣称传感器经过标定。

正常显示仍每 3 秒渲染，屏幕按独立周期发送缓存；设置阈值不会提前发布最新测量值。蜂鸣器在后续轮询按新高档判断，故障数据不能触发告警。污染值持续超高不会每轮重新启动鸣叫；回落或提高高档后解除锁存，再次超过时可重新触发。调整阈值不会中断已经开始的有限鸣叫，手动持续鸣叫及 PWM 调试覆盖保留原有优先级。

数值调试覆盖使用当前阈值选灯；直接写入的原始段 RAM 保持指定字节，不受阈值重绘。阈值保存在主控 RAM，重启恢复默认，不写入 Boot、OTA 暂存、元数据或其他 Flash 区域。需要跨重启保存时，由联网模块保存并在主控启动后重发。

## 原厂格式写入

Wi-Fi MCU → 主控，发送固定 12 字节二进制：

```text
23 CMD LOW_H LOW_L HIGH_H HIGH_L 00 00 00 00 00 21
```

`CMD=05` 设置甲醛，`CMD=06` 设置 PM；两整数均为大端。原厂式写入无成功应答，不能因串口发送成功就断言主控已接受；用下节新增查询核对。错误参数会沿运行时现有错误路径返回 `0x07`。

```text
# 甲醛 low=80、high=100
23 05 00 50 00 64 00 00 00 00 00 21
# PM low=35、high=75
23 06 00 23 00 4b 00 00 00 00 00 21
# 恢复默认值：甲醛 100/300、PM 75/150
23 05 00 64 01 2c 00 00 00 00 00 21
23 06 00 4b 00 96 00 00 00 00 00 21
```

上面是调用格式示例，不是推荐健康阈值。请发送对应的二进制字节，而非 ASCII 十六进制文本。Wi-Fi MCU 可在现有串口任务中串行发送：

```c
/* Example: HCHO low=80, high=100. All 12 bytes must be transmitted. */
uint8_t request[12] = {0x23, 0x05, 0x00, 0x50, 0x00, 0x64,
                       0, 0, 0, 0, 0, 0x21};
```

本仓库提供主控 UART 接口和离线组帧工具；不据此表示当前 Wi-Fi 固件已开放 HTTP/MQTT 阈值设置。现有 Wi-Fi 网络接口须另外对接这些帧及查询应答。

## 读取与能力识别

新增 `0x70/09` 请求，继承调试扩展的序号和应答格式：

```text
# SEQ=01，查询当前两种传感器阈值
23 70 09 01 00 00 00 00 00 00 00 21
# 默认值应答
23 70 09 01 00 00 64 01 2c 00 4b 00 96 03 00 00 00 00 00 21
```

| 应答绝对字节 | 含义 |
| --- | --- |
| 0–3 | `23 70 09 SEQ` |
| 4 | 状态：0 成功，1 参数错误，2 OTA 忙 |
| 5–6 / 7–8 | 甲醛 low / high，大端 |
| 9–10 / 11–12 | PM low / high，大端 |
| 13 | 功能位：bit0 可配置灯色，bit1 高档蜂鸣器告警，当前为 `03` |
| 14–18 / 19 | 清零 / `21` |

查询参数必须全零。`0x70/00` 能力位图由 `01ff` 扩展为 `03ff`，bit9 表示支持此查询；旧原厂 MCU 不支持 `0x70`。OTA 接收期间查询返回忙；升级已提交等待复位时不再应答新命令。读取成功证明主控 RAM 参数与功能支持，不证明实物灯色或鸣叫已验收。

离线组帧：

```sh
python3 tools/m1_debug.py threshold hcho 80 100
python3 tools/m1_debug.py threshold pm25 35 75
python3 tools/m1_debug.py --seq 1 thresholds
```

工具只输出 12 字节的十六进制表示，不自动操作串口或网络。

## 原厂证据与验证

`0x7f50–0x7fa2` 从接收缓冲 `0x2000008c` 读取字节 2–5，将甲醛两数写入 `0x200003a4/0x2000039c`、PM 写入 `0x200003a8/0x200003ac`，分别置标志 `0x200003b0/0x200003a1`。新工具执行 268 次原厂写入，包含 0、相等、反序和 65535；有效有序输入与当前 C 协议核心对照，反序输入检查拒绝且不改变状态。

另执行 72 次原厂正常渲染：改变阈值 RAM 及标志后，灯组不变，渲染路径未读取这些变量。这是所选渲染路径的证据，不宣称排除了全程序中的所有其他消费者。

```sh
build/analysis-venv/bin/python tools/verify_thresholds_stock.py /path/to/private-backup.bin
```

机器记录见 [threshold-stock-verification.json](threshold-stock-verification.json)。主机测试还覆盖默认全 16 位范围的颜色一致性、写入/读取字节序、独立分档、边界与告警、健康状态、3 秒快照、调试覆盖、OTA 忙及重启默认值。原厂备份仅用于本地模拟，不公开分发；实机启动、灯色与声音验证仍为 `NOT_RUN`。
