# 原厂外设和引脚

这里以 MCU 固件配置恢复结果为基础，用户实测结果单独标注，不是完整 PCB 原理图。PA/PB 是 ATSAMD20 引脚名，与 EMW3080 的 GPIO 编号不同。封装脚号需按实际封装和 [Microchip 引脚复用表](https://onlinedocs.microchip.com/oxy/GUID-2BBF0A73-A043-4A40-A6CA-0FF154E4BFFE-en-US-11/GUID-D350FD6F-9A6F-4025-903F-10E9CE79A524.html) 核对。

| 功能 | 外设 / 基址 | MCU 信号 | 复用 | 原厂初始化 |
| --- | --- | --- | --- | --- |
| 联网模块 UART | SERCOM3 `0x42001400` | TX PA22 / RX PA23 | C | `0x829c`，参数 115200 baud |
| 甲醛 UART | SERCOM4 `0x42001800` | TX PB08 / RX PB09 | D | `0x76f4`，9600 baud |
| PM UART | SERCOM1 `0x42000c00` | TX PA16 / RX PA17 | C | `0x7cb4`，9600 baud |
| 显示 I²C | SERCOM0 `0x42000800` | SDA PA08 / SCL PA09 | C | `0x71b4`，速率配置参数 100 |
| 温湿度 I²C | SERCOM2 `0x42001000` | SDA PA12 / SCL PA13 | C | `0x56bc`，速率配置参数 100 |
| 蜂鸣器 | TC1 `0x42002400` | PA11 | E | `0x7398` |
| 按键 | EIC EXTINT10 | PA10，低有效 | A / GPIO 读取 | `0x50ac` |
| 外部 RTC | GPIO 三线 | CE PA07 / CLK PB03 / DATA PB02 | GPIO | `0x51ac/0x51cc/0x51ec` |
| 联网模块使能/复位，用户已测通断 | GPIO | PA24 → EMW3080 CHIP_EN | GPIO | `0xb578` 置高、`0xb5a4` 置低 |

波特率来自调用参数与实际 Thumb 常量运算，不是仅凭字符串或反编译器推测。I²C 参数 100 尚未结合完整时钟树确认实测频率。

## PA24 与联网模块复位

2026-10-24，用户在本次样机上确认 ATSAMD20 PA24（48 脚封装第 33 脚）与 EMW3080 CHIP_EN（模块第 11 脚）相连。[庆科官方手册](https://docs.mxchip.com/attach/zh/DS0122CN_EMW3080_V2.9.pdf) 将 CHIP_EN 定义为低电平有效的使能复位脚。因此 PA24 拉低可使联网模块进入复位/禁用状态，拉高则释放；这不是对 Wi-Fi 配置执行恢复出厂设置。

原厂启动时在 `0xb68e` 调用置高函数。`0x16` 的非取消分支先延时 4000 RTOS tick，在 `0x8b0e` 调用置低函数，再延时 1000 tick 后请求 MCU 系统复位；该分支是否提交升级元数据另外取决于接收完成标志。升级超时定时器回调 `0x8220` 直接请求系统复位，没有调用上述置低函数。静态确认 SysTick reload=7999、时钟初始化 OSC8M / 1，据此为 1 ms/tick；真实时钟与复位期间的管脚波形尚未实测。

本次确认只覆盖 PA24 与联网模块 CHIP_EN 的连通；传感器是否共用该线、是否控制传感器电源仍未确认。开源 HAL 已实现启动置高、原厂结构的忙等待，以及有效 OTA 提交后 4000 ms→拉低→1000 ms→主控复位。未完成镜像不提交、不复位。MCU 复位时 GPIO 回到输入，不能声称整段 Boot 期间维持低电平；联网模块启动/复位波形尚未实测。

## 显示链路

地址配置值 `0x72`；`0x64a4` 的初始化发送数据为 `80 a0 9a 81 83 bf 88`。`0x7148` 的显示写入为 1 字节寄存器地址加 29 字节 RAM。该链路与之前观察到的 TM1680 架构相符，具体芯片仍以板上丝印为准。

`0x6638` 将亮度 25/50/75/100 映射到 `b1/b7/bb/bf`；显示关闭命令为 `82`，开启路径用 `83`。这些是显示控制字节，不是串口协议里的亮度值。

完整数字、日期、单位和负号段表已在 `src/display.c` 实现，完整 29 字节渲染通过原厂指令对照。用户实机确认：组 2 / `0x13` 为绿、组 3 / `0x12` 为黄、组 1 / `0x0c` 为红；甲醛掩码 `0x70`、PM 掩码 `0x85` 独立。数字与灯组共享字节，必须保留其他位。

每个区域都有左、中、右 3 个灯位，各灯位的红、绿、黄段可独立开关，共 9 个发光段；两区域合计 18 段。甲醛左/中/右分别对应上述颜色 RAM 字节的 `0x10/0x20/0x40`，PM 对应 `0x80/0x01/0x04`。新增格式显示协议按此映射写掩码，其他位保持。甲醛只有固定在首位之后的小数点，支持 `xxx` 或 `x.xx`；PM 只有三位整数。名称与原单位为独立段：甲醛 mg/m³、PM µg/m³，不能写任意文字或新增单位字形。新显示实现的灯段组合和共享位已纳入主机测试，实体屏幕仍需验收。

## 温湿度与外部时钟

温湿度地址 `0x44`，命令和 CRC 匹配 SHT3x，当前无法确定具体型号。传感器转换之外还存在原厂显示热补偿，直接使用标准换算公式不等于复现原厂显示。`src/climate.c` 已移植原厂四状态定点模型并通过连续状态/输出对照，驱动策略见 [implementation.md](implementation.md)。

名叫 `i2c_rtc` 的任务并未证明 RTC 使用 I²C。`0x5260` 低位先发，`0x52c0` 读取，通过 `0x80/0x81` 至 `0x8c/0x8d` 的成对寄存器及 `0x8e` 访问 BCD 时间字段，符合 DS1302 兼容的三线接口。不能与 SAMD20 内部 RTC 外设混淆，具体外部芯片仍需丝印确认。

## 实物核对清单

1. 记录板号、MCU 和各传感器/显示/RTC 芯片丝印，测量信号连通；不要沿用其他板版本的脚号结论。
2. 被动捕获联网 UART、两路传感器 UART、两路 I²C 和 RTC 三线，核对速率与时序。
3. 在新固件上同步记录显示值、各段形/灯色与 RAM，验证已恢复的映射。
4. 测量按键消抖/长按、蜂鸣器频率、显示开关前后温湿度补偿。

上述是新固件的后续硬件验收，本次没有执行这些操作；用户提供的原厂灯色对应和 PA24–CHIP_EN 连通结果已单独标明。
