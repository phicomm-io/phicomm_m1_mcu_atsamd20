# 读取完整传感器帧

主控在正常采集路径缓存完整响应，电脑通过现有 Wi-Fi `POST /api/v1/mcu/exchange` 只读获取并输出 JSON。不发送新的传感器命令，不改变采样周期、PM 预热/突变过滤、显示补偿和告警策略。需支持网络桥接的 Wi-Fi 固件，以及声明传感器读取 schema 1 的主控构建；工具会先检查能力，不凭版本号猜测支持。

```sh
# 如设置了网页密码，先 export M1_WEB_PASSWORD='你的网页密码'
python3 tools/m1_sensors.py --host DEVICE_IP --device-id DEVICE_ID
python3 tools/m1_sensors.py --host DEVICE_IP --device-id DEVICE_ID --sensor pm
# 离线解码已捕获的完整帧，不连接设备
python3 tools/m1_sensors.py --sensor pm --hex '42 4d ...'
```

网络读取先核对 M1 型号和设备 ID。输出保留 `raw_hex`，并包含缓存代数、帧龄、当前传感器健康、校验/错误/预热/过滤标记。测量数据超过 6 秒、当前健康无效或正在预热/过滤时，`usable_for_measurement` 为 false。没有采集到的响应返回 `captured=false`，不填造零读数；探测响应通常只在启动/重试时出现。各类响应分别缓存，不保证三类传感器同时采样。

## 已解码字段

| --sensor | 帧与字段 |
| --- | --- |
| pm | 完整 32 字节、帧长、校验；标准 Plantower 兼容布局的 CF=1 与大气环境 PM1.0/PM2.5/PM10（μg/m³）；大于 0.3/0.5/1/2.5/5/10 μm 的累计颗粒数（每 0.1 L）；版本字节与错误字节 |
| hcho | 完整 9 字节 0x86 响应、未经过 M1 低值显示处理的原始浓度、未知字节 4–7 与校验 |
| sht | 完整 6 字节 0x2400 测量响应、两个 16 位原始字和 CRC；按 SHT3x 标准公式换算的温湿度（未加 M1 显示热补偿） |
| sht-status | 完整 3 字节 0xf32d 响应、CRC、状态字；写校验/命令失败、复位检测、温度/湿度告警、加热器与待处理告警位 |
| sht-aux | 完整 6 字节 0x3682 响应、两个原始字及各自 CRC 检查；不命名其物理含义 |
| hcho-probe | 9 字节 0x78 探测应答，保留未知载荷，验证 8 位校验 |
| pm-probe | 8 字节原厂探测识别应答，保留未知载荷；仅匹配原厂识别模式，不宣称已验证其校验算法 |

PM 额外字段按 [Plantower 厂家协议](https://cdn-shop.adafruit.com/product-files/3686/plantower-pms5003-manual_v2-3.pdf) 解码。实机模块型号与这些字段的实际支持/精度需独立验证，字段为零不等于已确认不支持。固件 C 接口 `m1_pm_decode()` 验证头、长度、校验后返回全部字段，包括带错误码的帧；旧 `m1_pm25_raw()` 仍拒绝错误帧。原厂 0x19 甲醛查询保留。

SHT 标准公式为 `T=-45+175*raw/65535`、`RH=100*raw/65535`，来源为 [SHT3x-DIS 手册](https://sensirion.com/media/documents/213E6A3B/63A5A569/Datasheet_SHT3x_DIS.pdf)，结果不能与 M1 原厂补偿后的显示值混为一谈。0x3682 的 CRC 异常只反映在诊断结果中，不改变既有补偿路径；不把未知字节解释为新传感器测量。

## 0x70 / OP 0x10：分块读取协议

沿用 12 字节请求、20 字节应答与序号匹配。OP00 的 D6=传感器 schema（1）、D7=帧种类数（7）、D8=每块最多字节数（9）；D0 仍为原有扩展协议版本 2，D1–2 的 16 位位图只描述 OP00–0f，不包含 OP10。

请求参数 A0=传感器 ID（依上表 0–6），A1=模式，A2=偏移，A3=数量，A4–5=大端缓存代数，A6=0。

- A1=0：读取元数据，A2–6 必须为 0。返回 D0=ID、D1=长度、D2–3=代数、D4–7=帧龄 ms、D8=标记、D9=当前健康，其余清零。没有缓存时长度/标记为 0，帧龄为 0xffffffff。
- A1=1：读取数据，数量 1–9，偏移/数量不得超出实际长度，代数必须匹配。返回 D0=ID、D1=偏移、D2=数量、D3–4=代数、D5 起最多 9 字节数据。
- 标记 bit0=已缓存，bit1=校验通过，bit2=PM 错误码非零，bit3=PM 预热，bit4=PM 突变被过滤。
- v1 的 PM2.5 正常显示和 `0x01` 查询经过中值与定点平滑，完整帧里的 PM2.5 仍为传感器原始值。bit4 标记当前大幅原始突变未通过中值确认；普通平滑不会设置该位，不因此使 PM1.0、PM10 和颗粒数失效。算法和响应边界见[采集与数值节奏](sensor-cadence.md#v1-pm25-稳定处理)。
- STATUS=5 表示代数改变，需要重新读取元数据和所有数据块；参数非法仍为 1，OTA 忙为 2。不支持的主控返回 3。

电脑工具在读完后再次检查代数，最多重试三轮，避免将不同采集周期的片段拼成一帧。16 位代数回绕；该机制针对短时间查询，不作为跨重启或长时间缓存的唯一标识。缓存发生在主循环消费的完整响应处，不代表捕获线路上的每个字节或每个被丢弃帧。
