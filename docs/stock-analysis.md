# M1 主控原厂逻辑分析

分析日期：2026-10-24。所有地址均为 MCU 主 Flash 的绝对地址，Thumb 函数入口用偶数表示；向量表中的入口最低位为 1。结论仅适用于 [stock-image.json](stock-image.json) 的 SHA-256。原厂镜像不公开分发。

本文区分“指令确认”“模拟对照”和“实物验证”。引脚配置与控制流来自备份指令；CRC、部分显示逻辑和采样编码另有模拟对照；本仓库尚未刷入设备，不把模拟结果称为硬件验证。

## 启动、内存与任务

本次 SWD 读取识别为 ATSAMD20G18A，主 Flash 256 KiB、SRAM 32 KiB。早期依据其他设备资料推测的 G17A 不适用于本次备份。文件长度为 `0x40000`，最后一个非 `0xff` 字节在 `0xc077`；空白部分不代表没有预留升级区。

| 项目 | 地址 / 值 | 依据 |
| --- | --- | --- |
| Boot 向量 | SP `0x20002130`，Reset `0x829` | 文件起始 8 字节 |
| Boot 主流程 | `0xa64` | 检查升级标志，然后搬运或跳转 |
| 应用向量 | `0x4000`，SP `0x20006408`，Reset `0xb4d1` | 向量表 |
| 应用主流程 | `0xb5fc` | 任务创建调用 |
| 应用初始化数据 | Flash `0xbed4` → SRAM `0x20000000`，长 `0x1a8` | 启动复制表 |
| 应用 BSS | `0x200001a8` 至 `0x20004404`，末地址不含 | 启动清零表 |
| 原厂版本 | `11.1.2.1`，字符串在 `0xbdd0` | `0x11` 返回路径 |

应用采用 FreeRTOS 风格的任务/信号量/软件定时器结构；存在 `Tmr Svc` 和 Idle 路径，尚未确定内核精确版本。`0xb5fc` 创建如下十个任务：

| 名称 | 入口 | 工作 |
| --- | --- | --- |
| `led_task` | `0x7320` | 显示 RAM 更新与发送 |
| `jq_task` | `0x7824` | 甲醛传感器收发与处理 |
| `pm25_task` | `0x7df0` | PM 传感器收发与处理 |
| `i2c_th` | `0x6334` | 温湿度采集与换算 |
| `i2c_rtc` | `0x5370` | 外部 RTC；实际为三线 GPIO 协议 |
| `sem_task` | `0x7594` | 周期唤醒、分频与喂狗 |
| `up_task` | `0x83d8` | 联网模块接收/分派 |
| `up_sub_task` | `0x8534` | 返回帧、事件和升级处理 |
| `pwm_task` | `0x7440` | 蜂鸣器模式 |
| `button_task` | `0x5160` | 按键事件处理 |

`sem_task` 每隔 1000 个 RTOS tick 唤醒甲醛、温湿度、RTC 路径，每第三轮触发 PM/显示相关工作，并喂看门狗。这是调度间隔，不能直接等同于各传感器实际采样间隔。本次确认 SysTick 配置 `0x925c` 写 reload=7999，`0xb020` 配置主 GCLK 源 6（OSC8M）、除数 1 且 OSC8M prescaler=0，CPU 分频=0，静态推导 1 ms/tick；尚无波形实测。

## 传感器与采样

串口、I²C 与 GPIO 分配见 [hardware.md](hardware.md)。

- **甲醛**：`0x7824` 使用 SERCOM4，初始化探测请求为 `ff 01 78 41 00 00 00 00 46`，常规请求为 `ff 01 86 00 00 00 00 00 79`。接收函数 `0x762c` 检查首字节 `ff` 和 8 位加法校验，读取字节 2–3 的大端值到 `0x2000408c`，并更新状态 `0x200002ad`。采样帧返回的是另一个处理后变量 `0x20004084`。存在低值/零值显示处理，不能把原始值与显示值混同。尚未确认具体传感器型号及全部处理公式。
- **PM2.5**：`0x78cc` 处理 32 字节 `42 4d` 帧，校验前 30 字节累加值与最后两字节、检查第 29 字节错误信息，从第 12–13 字节取值。符合 Plantower 兼容帧布局，不能据此确定型号。模式 2 使用对齐 32 字节接收，四帧预热，不做突变过滤；模式 3 在 64 字节窗口的前 32 个偏移搜索帧，两窗口预热并过滤突升。两种路径均已移植，流解析/预热计数的调度差异见实现说明。模式 4 的八字节探测应答检查首两字节及字节 6–7=`01 74` 后切 2，否则切 3；任务入口初始化模式 3。新自动重试策略不当作已确认的原厂模式 4 触发流程。任务中另有探测请求 `42 4d e2 00 00 01 71`，不把它擅自解释为已确认的传感器配置能力。
- **温湿度**：地址 `0x44`，命令 `f3 2d` 和 `24 00`，每个 16 位原始字带 CRC8，函数 `0x5660` 使用初值 `ff`、多项式 `31`。匹配 SHT3x 协议，无法仅凭协议区分 SHT30/31 等型号。换算路径在 `0x58c4`，还依赖显示开关：`0x58a8` 在显示开启时写入补偿输入 1000，关闭时写入 0。原厂四状态定点补偿已移植并通过连续状态/输出对照；`0x5868` 状态查询/三字节读取/CRC 检查也已接入。软复位限流恢复是依据 SHT3x 官方手册新增的策略，不声称已恢复原厂全部故障分支。

`0x8534` 中 `0x85a0–0x85ec` 构造采样返回。PM、甲醛、温湿度状态分别来自 `0x20000328`、`0x200002ad`、`0x200001f0`。部分路径把状态置位后保持，尚未完整确认故障清零/超时语义，因此这些是原始状态标志，不能直接当作“此刻健康”的证明。负温度独立携带符号位，详见协议。

## 显示、灯组与阈值

`0x72d4` 顺序调用日期 `0x66dc`、时间 `0x68b8`、甲醛 `0x6ad8`、PM `0x6dac`、温度 `0x6f3c`、湿度 `0x705c` 渲染。数字段选择函数 `0x66a0` 和完整渲染已重建并经过指令对照。`0x7148` 发送一个寄存器地址字节和 29 字节显示 RAM。

已确认两组灯共用三个 RAM 字节，但使用互不重叠的位：

| 灯组 | RAM 偏移（不含首个寄存器地址字节） | 甲醛掩码 | PM 掩码 |
| --- | --- | --- | --- |
| 1 | `0x0c` | `0x70` | `0x85` |
| 2 | `0x13` | `0x70` | `0x85` |
| 3 | `0x12` | `0x70` | `0x85` |

写灯组函数分别为 `0x69c4` 和 `0x6c90`；参数 9 点亮该类全部三组，写入保留其他数字位。用户另行提供实机确认：组 2 / `0x13` 为绿，组 3 / `0x12` 为黄，组 1 / `0x0c` 为红。这一颜色命名依据用户实测，不是从指令推断。

| 渲染输入原始整数 | 组 2 | 组 3 | 组 1 |
| --- | --- | --- | --- |
| 甲醛 | ≤100 | 101–300 | ≥301 |
| PM2.5 | ≤75 | 76–150 | ≥151 |

上表是指令中的整数比较，不替代传感器单位/标定验证。阈值边界和灯组掩码已经模拟对照。高值路径还会依赖锁存状态触发蜂鸣器；当前纯灯组函数没有实现联动蜂鸣。

**`0x05/0x06` 可以写阈值变量，但尚未发现它们驱动灯组比较。** 接收路径写入 `0x200003a4/0x2000039c`（甲醛）和 `0x200003a8/0x200003ac`（PM），并设标志；上述渲染函数却直接比较固定立即数。当前证据支持“接收并保存”，不足以支持“设置后改变灯色”。开源核心暂时保存 RAM 值并维持已验证的固定灯组规则。

## 按键与蜂鸣器

PA10 为低有效按键，EIC EXTINT10，初始化在 `0x50ac`。`0x5104` 创建周期为 10 tick 的 `buttontimer`；回调 `0x4f4c` 计数，释放路径 `0x4fa8` 判断：

| 条件 | 原厂行为 |
| --- | --- |
| 释放且计数 6–299 | 切换显示，发送 `0x0f` 状态事件 |
| 计数到 301 | 唤醒按键任务，进入长按处理路径 |
| 释放且计数 ≥900 | 排队 `0x18`，通知联网模块进行网络重配 |
| 计数到 1000 | 排队 `0x10`，设置显示空白相关状态 |

这是原厂状态机片段，不能把每一行独立视为互斥按键操作。按本次静态推导的 1 ms tick，900 次约 9 秒；尚需验证全部按住/释放与锁存组合。配网本身由联网模块完成，MCU 只发事件。当前开源运行时已实现定时、消抖、短按及长按状态机；采用的毫秒时间和显示处理见 [实现说明](implementation.md)，尚未与原厂全部分支逐项核准。

`0x0e` 将蜂鸣器状态设为 0 或 1，唤醒 `0x7440`：状态 0 停止 TC；状态 1 开启后无本地定时停止；内部状态 2 开启 200 tick；状态 3 使用 200/400/200 tick 的序列并重复 8 次。TC 初始化在 `0x7398`，输出 PA11。**普通 `0x0e` 不是已确认的“响一声”命令**；实际频率、声响和时长需测量时钟与波形。

## 原厂 MCU 更新链路

| 区域 | 地址 | 确认程度 |
| --- | --- | --- |
| Boot 保留区 | `0x00000–0x03fff` | 应用从 `0x4000` 启动 |
| 主应用槽 | `0x04000–0x21fff` | 搬运目的起点和暂存起点确定；槽末由布局推定 |
| 暂存区 | 起点 `0x22000` | 块写目的地址确定；不能认为整个剩余 Flash 都可用 |
| 升级元数据行 | `0x3ff00–0x3ffff` | 标志、长度与擦除行确定 |

`0x7e68/0x8534` 处理 `0x12–0x17` 升级事务。`0x12` 设置完整 256 字节块数和尾块长度；`0x13` 携带块序号、负载和 CRC，按 `0x22000 + (序号−1)×256` 写暂存区。Flash 页面为 64 字节、擦除行为 256 字节，写后回读检查。

校验函数 `0x84e0/0x8510` 使用多项式 `0x1021`，但移入数据位的方式不同于常见 CRC-16/CCITT-FALSE。缓冲区路径从 0 开始，勿直接套用同多项式库函数；公开 `m1_stock_crc_byte` 已做 512 例原指令对照。

完成后 `0x84a0` 在 `0x3ff00` 写标志 1、两个大端长度字节；Boot `0xa64` 经 `0x900/0x92c` 读取，调用 `0x970` 将暂存复制到 `0x4000`，再复位。搬运循环是 `(length >> 6) + 4` 个页面，**不能简化为向上取整长度**；每页有回读比较，结束擦除元数据行。

元数据长度只有 16 位，尽管 Boot 中另有 `0x1de00` 的范围比较，也不能据此声称可升级同样大小的应用。新工程暂把链接可用应用区限制为 `0xffff` 字节，同时保留 Boot、暂存和元数据区域。新打包器已按此限制生成原始应用负载并通过升级/Boot Flash 模型；实机 OTA 未验证。

目前未在上述升级路径确认数字签名或公钥校验；CRC 和回读比较只证明传输/写入检查。尚未完成所有异常路径与掉电行为分析，不宣称任意镜像均能成功更新，也未发现已确认的串口读出 Flash 命令。开源工程已实现独立升级/Boot，额外使用 CRC32 日志；该实现及恢复限制见 [implementation.md](implementation.md)，不等于已证明原厂所有异常路径。

## 复现和待解问题

入口、任务表和字符串可用 `tools/analyze_stock.py` 复现。`tools/disassemble.py` 用于按地址查看 Thumb 指令，`tools/verify_stock.py` 在不映射 MMIO 的模拟内存执行选定代码，结果见 [validation.md](validation.md)。

已补齐数字段表、四状态温湿度补偿、甲醛低值处理、PM 两种接收模式、状态查询与新增恢复策略，PA24 原厂时序已接入。仍需核实阈值其他消费者、原厂模式切换触发链及原厂 OTA 全部异常路径。PA24 用户确认连接联网模块 CHIP_EN，传感器是否共用未确认。引脚与静态时钟配置不能代替新驱动的物理波形验收。新增 PM/PA24/SHT 指令对照工具见 [验证记录](validation.md)。
