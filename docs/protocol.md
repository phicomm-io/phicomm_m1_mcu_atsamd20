# 联网模块与 MCU 协议

原厂入口与字段来源对应 [stock-image.json](stock-image.json)。新运行时沿用普通帧格式，升级由单独的可变长解析器处理。这里是主控 UART，与 EMW3080 网络 OTA 是不同层次。

## 普通帧

联网模块 → MCU 固定 12 字节：`f0=23`，`f1=命令`，`f11=21`。MCU → 联网模块固定 20 字节：`f0=23`，`f1=命令/事件`，`f19=21`，未使用字段清零。数值均为十六进制字节表示，普通帧无另一个独立校验字段。

采样返回 `0x01`：

| 字节 | 含义 |
| --- | --- |
| 2–3 | 处理后的甲醛整数，大端 |
| 4 | 温度负号，1 为负 |
| 5 / 6 | 温度绝对值整数 / 百分位 |
| 7 / 8 | 湿度整数 / 百分位 |
| 9–10 | PM2.5，大端 |
| 11 / 12 / 13 | PM / 甲醛 / 温湿度健康标志 |
| 14–18 | 预留，清零 |

例如 `f4..6=01 05 32` 表示 −5.50°C。原厂状态有锁存分支；新固件则在三次失败或 6 秒失效后清零，收到有效采集后置 1。数据保留最后值时，应同时看健康字段。

| 命令 | 方向/功能 | 新固件行为 |
| --- | --- | --- |
| `01` | 查询/采样 | 返回处理后采样、符号、健康字段 |
| `02` | 显示配置 | f2=0/25/50/75/100；f3=0关闭/1开启/2切换；退出全段测试 |
| `03` | 设置时间 | f2–3 大端年，f4–8 月日时分秒；校验后写 RTC |
| `04` | MCU 长按事件 | 新按键状态机达到 3010 ms 发出；不当作普通查询命令 |
| `05` / `06` | 甲醛/PM 两级阈值 | f2–3 低、f4–5 高，大端；RAM 保存，低值须小于高值；固定灯色不变 |
| `07` | 错误通知 | `errorup`，f9/f10=`ff`；帧/升级错误 |
| `08` / `09` | 甲醛/PM 超时通知 | `errorjq` / `errorpm`，f9/f10=`ff` |
| `0a` / `0b` | 甲醛/PM 无效帧通知 | 同上字符串，f9/f10=`ee` |
| `0c` | MCU 主动时间 | 字段同 `03`；每秒发送，OTA 事务期间暂停 |
| `0d` | 查询时间 | 返回 RTC 同步后的 RAM 时钟；RTC 故障时 RAM 续时 |
| `0e` | 蜂鸣器持续开关 | f2=0停，非零开；驱动实际 TC 输出 |
| `0f` | MCU 短按切屏事件 | f2 为显示开关状态 |
| `10` | 全段测试/长按通知 | 输入参数同 `02`，进入全段显示；长按事件不带新参数 |
| `11` | 查询版本 | f2=长度，f3 起为 tag 版本 + 六位 hash，如 `0.9.0-abcdef`；脏构建末尾 `-d`，最多 16 字符，见 [版本规则](versioning.md) |
| `12`–`16` | 主控升级 | 见下文 |
| `17` | MCU 启动公告 | 初始化后发送 |
| `18` | 网络重配事件 | 长按释放触发，由联网模块实施配网 |
| `19` | 原始甲醛查询 | f2–3 原始整数，大端，独立于显示低值处理 |
| `70` | 新固件调试扩展 | PWM、屏幕数据/段、诊断、PM 模式，见 [调试协议](debug-protocol.md) |
| `1a` | 升级取消确认 | `0x16 f2=1` 的返回 |

显示模式 2 为新固件明确实现的切换语义；原厂存在模式 2/锁存分支，但未完成所有组合和时序对照。校验与事件节奏的有意差异见 [implementation.md](implementation.md)。

## 升级

- `0x12` 普通帧：f2 为完整 256 字节块数，f3 为尾负载字节数，整体长度 164–65535 字节。
- `0x13` 可变长：f2–3 为从 1 开始的大端序号，f4 起负载，末尾两字节大端 CRC。完整帧 262 字节；尾帧为余数字节数 +6，余数零也发送 6 字节尾帧。升级块不使用普通帧的 f11 尾标记。
- CRC 为初值 0、多项式 `0x1021` 的 bit-input 变体（逐位移入负载），不是 CCITT-FALSE。
- `0x14` 应答：f2–3 回显序号，f4=1 表示成功；f5=1 表示 CRC 错，f5=2 表示旧块/序号错误。旧块经回读匹配可以同时 f4=1、f5=2。其他写入/状态错误返回 f4=0，不能当作成功。
- 最后尾块成功后再发 `0x15 f2=1`。这只表示接收完成，不表示新应用已运行。
- `0x16 f2=1` 取消并返回 `0x1a`；其他值验证完整暂存、提交元数据，等待 4000 ms 拉低 PA24/CHIP_EN，至少保持 1000 ms 后复位；进入等待后不接受新命令。30 秒无有效进展取消事务。
- 普通主动时间与传感器错误通知在升级期间暂停，查询/升级应答仍可发。具体区域、扩展日志、原厂 Boot 兼容性及恢复限制见 [implementation.md](implementation.md)。

CI 产物和 Wi-Fi MCU 发送步骤见 [ota.md](ota.md)。

## 可移植接口

`m1_command()` 只处理普通协议状态，返回 `M1_BAD_FRAME` / `M1_UNSUPPORTED` / `M1_APPLIED` / `M1_REPLY`；仅 `M1_REPLY` 生成可发送的 20 字节返回。不能直接对它输入任意长度升级块。

应用应初始化 `m1_runtime`，向 `m1_runtime_rx()` 按通道输入字节及接收时间，再周期调用 `m1_runtime_poll()`。该层执行真实 I/O 回调及升级事务。`m1_runtime_rx_error()` 清通道解析状态；`m1_runtime_beep()` 提供停止/持续/单次/重复模式。调用需串行，I/O 回调须完整且有效。MCU HAL 用中断队列隔离中断与运行时，运行时本身不在 ISR 内执行。
