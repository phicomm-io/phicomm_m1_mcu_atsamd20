# 联网模块与 MCU 串口协议

本说明对应 [stock-image.json](stock-image.json) 的原厂主控镜像。接收入口 `0x7e68`，发送入口 `0x8534`。方向以 MCU 为中心；不是 EMW3080 自身的网络 OTA 协议。

## 普通帧与采样

联网模块 → MCU：普通帧固定 12 字节，`f[0]=23`、`f[1]=命令`、`f[11]=21`，中间为参数。MCU → 联网模块：普通帧固定 20 字节，`f[0]=23`、`f[1]=命令/事件`、`f[19]=21`，其余预留字节一般清零。普通帧未发现独立校验字段；`23/21` 是十六进制字节，不是长度。升级 `0x13` 是例外，不能用普通 12 字节解析器处理。

命令 `0x01` 返回：

| 字节 | 意义 | 原厂 SRAM 来源 |
| --- | --- | --- |
| 2–3 | 处理后甲醛整数，大端 16 位 | `0x20004084` |
| 4 | 温度符号，1 为负 | `0x20004094` 起的三字节 |
| 5 / 6 | 温度绝对值整数 / 百分位 | 同上 |
| 7 / 8 | 相对湿度整数 / 百分位 | `0x20004088` |
| 9–10 | PM2.5，大端 16 位 | `0x20004080` |
| 11 | PM 状态原值 | `0x20000328` |
| 12 | 甲醛状态原值 | `0x200002ad` |
| 13 | 温湿度状态原值 | `0x200001f0` |
| 14–18 | 预留 | 清零 |

温度解码为 `sign × (f[5] + f[6]/100)`；例如 `f[4..6]=01 05 32` 是 −5.50°C。状态位存在锁存路径，不能单凭非零声称当前样本新鲜或传感器完好。

## 升级帧边界

原厂 `12` 配置完整 256 字节块数和尾块字节数。`13` 使用 `f[2..3]` 大端块序号，`f[4..]` 为负载，最后两个字节是 CRC，完整块帧长 262 字节，尾块长为尾负载加 6；它不沿用普通帧尾的解析条件。原厂 CRC 是 `0x1021` 多项式的逐位移入变体、初值 0，**不是 CRC-16/CCITT-FALSE**。

目前这些是分析记录，不是经过端到端验证的烧录工具接口。特别是长度限制、填充页、重复块、超时、断电和异常复位还需验证。开源核心对这些命令返回 `M1_UNSUPPORTED`，不做 Flash 写入。Boot/暂存与元数据布局见 [stock-analysis.md](stock-analysis.md)。

## 新核心的调用约定与有意差异

使用零初始化的 `m1_stream stream = {0}` 输入字节；`m1_feed` 在拿到有效普通帧时返回 true，错误帧会搜索下一个帧头恢复。`m1_init` 初始化状态，`m1_command` 返回：

- `M1_BAD_FRAME`：边界或已实现命令的参数无效，状态不变。
- `M1_UNSUPPORTED`：未实现的命令，状态不变。
- `M1_APPLIED`：仅状态更新，没有生成可发送返回。
- `M1_REPLY`：生成了完整 20 字节返回。

只有 `M1_REPLY` 才能把 `reply` 当作本次命令结果发送；其他返回不保证该缓冲区被改写。样本、时钟和事件 API 也可直接构造完整返回。调用者负责合法指针、串行访问和状态同步，结构体字段不得未经初始化使用。

新核心限制亮度为 0/25/50/75/100、显示开关为 0/1；原厂另有值 2 的路径，尚未移植。时间限制为 2000–2099 的有效日期，设置阈值要求低值小于高值。阈值、时钟和蜂鸣器只驻留 RAM，RTC 不自动走时。原始传感器解码额外要求甲醛命令字 `86`、PM 长度字段 28，比目前确认的原厂回调检查更严格。

`m1_display_groups` 的有效灯组为 1/2/3/9，其他输入会清除该类灯组；不宣称无效参数行为与原厂一致。`m1_sht_raw` 只输出传感器原始字，不执行原厂补偿。GPIO、校准、调度、数字显示与蜂鸣器模式尚未落地。
