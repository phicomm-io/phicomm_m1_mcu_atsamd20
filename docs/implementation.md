# 运行实现及与原厂的差异

本记录对应 `oss-0.3`。代码完成与实物验收是不同层次；当前没有执行 SWD 写入、设备 OTA 或实机外设测试。

## 分层

- `src/core.c`：普通命令、状态和编码；自身不访问外设。
- `src/debug.c`：`0x70` 调试扩展、PWM/屏幕覆盖租期、诊断与 PM 模式选择。
- `src/runtime.c`：收帧、采集与恢复、调度、显示和按键、事件、告警、OTA 事务。
- `src/climate.c`：从原厂 `0x58c4` 观察到的四状态定点补偿。状态/输出通过连续指令对照，不调用原厂代码。
- `src/display.c`：完整数字段表和 29 字节 RAM，保留共享位并独立选灯。
- `src/rtc.c`：BCD 编解码与日历走时。
- `src/update.c`：抽象 Flash 上的更新接收、提交、校验及 Boot 搬运。
- `platform/samd20.c`：基于官方设备头文件/CMSIS 的真实寄存器驱动。
- `platform/main.c`、`platform/boot.c`：应用与独立 Boot 入口；分别链接于 `0x4000` 与 `0`。

## 驱动和运行策略

CPU 使用保留校准值的 OSC8M 8 MHz，SysTick 1 ms。WDT 由 OSCULP32K / 32 提供 nominal 1024 Hz，8192 tick 约 8 秒，主循环喂狗。UART 配置保持原厂波特率。每路 RX 环形队列 512 槽（可用 511），保存每字节接收时刻；TX 256 槽。错误/溢出清空该通道解析状态，接收处理每轮每通道最多 128 字节，发送容量不足则计数并返回失败。

I²C 使用约 100 kHz，轮询/同步等待有上限；失败后以开漏 GPIO 释放 SDA/SCL、发九个 SCL 脉冲和 STOP，再初始化控制器。不会把总线强驱动到高电平。PA24 已由用户确认连接联网模块 CHIP_EN。HAL 先预置 OUT 高再使能输出，避免方向切换产生低脉冲；随后保留原厂 1000×1500 的减计数/比较/分支等待，再初始化串口。启动等待保持指令结构，不把它另行标成实测毫秒数。传感器是否共用未确认，见 [硬件记录](hardware.md)。屏幕失败后延迟 1 秒重新初始化。RTC 采用三线 LSB-first、BCD 突发读写，设置后回读确认；读失败计数并让 RAM 日历继续走时。

甲醛发送最多三次 `ff 01 78 41 00 00 00 00 46` 探测，间隔 500 ms；之后每秒发送 `ff 01 86 00 00 00 00 00 79`。`0x19` 返回原始值。显示刷新维持低值首次 0、之后 10 的原厂处理，超过 9999 显示三个 9 并保持之前处理后返回值。即使后者保留旧值，原始查询仍返回最新值。

PM 两种模式均使用 `42 4d`、长度 28 的 32 字节帧，前 30 字节累加校验。模式 2 跳过四帧，此后直接发布数值；模式 3 跳过两帧，此前值 ≤149、当前值 ≥1001 时保留一次上一值，下一帧确认。有效校验但传感器错误字节非零时发布 0 并累计失败。默认模式 3；每 10 秒发 `42 4d e2 00 00 01 71`，自动模式在接下来 1 秒内识别原厂八字节应答的 `42 4d` / 字节 6–7=`01 74` 条件后切换模式 2、重新预热。无应答保留当前模式，原厂任务本身固定从模式 3 启动，自动探测的重试周期是新策略。`0x70/07` 可强制 2/3 或恢复自动。接收按字节流恢复边界，坏候选保留下一首字节，能处理原厂 64 字节窗口中非零偏移的有效帧；不复制原厂多个候选间校验累加器残留等异常行为。原厂模式 3 按 64 字节回调窗口跳过两次，新固件按有效 32 字节帧跳过两次，这是保留的调度差异。

温湿度每轮先发 `0xf32d`，等待 1 ms 后读 3 字节并校验 CRC8，保存状态字；状态位 0/1 失败则不发布该轮。原厂 `0x5868` 确认有状态请求/三字节读取/CRC 检查，但没有据此实现以下完整恢复策略。成功后 `0x2400` 触发，20 ms 后读带 CRC 的六字节原始值；再发送原厂额外命令 `0x3682`，2 ms 后读六字节，打包字节 0/1/3/4 作为补偿输入。额外数据的物理意义没有据此命名。补偿模型约每秒更新，真实显示有效开关（包括调试覆盖）为输入。状态字通过 `0x70/06` 查询，不能用它代替采集健康字段。

连续三次失败或 6 秒无有效采样，安排 `0x30a2` 软复位，至少等待 2 ms 后重新从状态查询开始；发出复位之间至少 10 秒，NACK 也限流。只恢复传感器，不清除热补偿历史，不复位联网模块；直到收到完整有效转换才恢复健康。状态位 4/15 单独置位不会触发复位风暴。这是依据 [Sensirion SHT3x-DIS v7](https://sensirion.com/media/documents/213E6A3B/63A5A569/Datasheet_SHT3x_DIS.pdf) 的新增恢复策略，软复位命令和最大 1.5 ms 等待来自官方资料，不冒充已逐指令确认的原厂恢复顺序。异常模型状态或温度越界不提交样本。低 64 位乘法溢出用无符号运算明确表达，避免 C 的有符号溢出未定义行为。

连续三次坏帧/采集失败，或超过 6 秒没有有效样本，使对应健康字段清零；有效样本恢复为 1。甲醛和 PM 生成原厂格式错误消息，温湿度通过健康字段表示；不捏造第三种原厂错误码。超时/失败计数保留在运行结构中。显示可保留最后有效数值，健康字段同时表示失效。

## 显示、按键和蜂鸣器

数字段表为 `f5 05 b3 97 47 d6 f6 85 f7 d7`。日期、时间、甲醛、PM、温度、湿度、单位和负号都已生成；PM 消除前导零，负温度显示到 −9.9°C，超出时沿用原厂负号加 9.9 的段形限制。查询帧仍携带真实温度。`0x10` 为全段测试，`0x02` 退出测试并恢复正常显示。

用户确认组 2 / RAM `0x13` 为绿，组 3 / `0x12` 为黄，组 1 / `0x0c` 为红。甲醛 `0x70`、PM `0x85` 独立；分别使用固定阈值 100/300、75/150。`0x05/0x06` 仅保存 RAM 配置，原厂尚未找到实际阈值消费者，因此不把它们假装接到固定灯色或告警判断上。

PA10 低有效，EIC 双边沿与 GPIO 实际电平结合，20 ms 消抖。新调度策略：短按 60–2999 ms 切屏并通知 `0x0f`；按住达到 3010 ms 通知 `0x04`；达到 10000 ms 全段测试并通知 `0x10`；释放时若已按住至少 9000 ms，通知 `0x18`。网络重配由联网模块执行。原厂存在这些分支；本次进一步确认 SysTick reload=7999，主时钟初始化选择 OSC8M、不分频，据此静态推导 tick 为 1 ms。上述毫秒策略仍未与原厂全部锁存/释放分支和物理波形逐项核准。

蜂鸣器使用 TC1 WO1 / PA11，8 MHz / 2，周期 2000、占空比 50%，目标约 2 kHz。`0x0e` 持续开关；`m1_runtime_beep()` 还提供 200 ms 单次和重复告警。新重复策略为每 800 ms 的前 200 ms 和末 200 ms 响，重复八组。健康甲醛 >300 或 PM >150 从正常跨入告警时触发一次序列，持续手动开启优先；回落后重新允许告警。**频率/节奏及阈值策略尚未做实物声音对照。**

新增 `0x70` 可以控制 PWM 频率/占空比/持续时间、覆盖显示值/段 RAM、读取诊断及选择 PM 模式；带超时恢复并在 OTA 开始时退出覆盖。完整字段、示例及离线组帧工具见 [debug-protocol.md](debug-protocol.md)。

## OTA 事务与 Boot

1. `0x12` 建立长度与块事务；只接受 164–65535 字节。应用向量还必须通过栈范围/8 字节对齐、Thumb 入口及入口在镜像内的检查。
2. `0x13` 按序接收 256 字节块，尾块为余数，序号从 1 开始；即使余数为零也有最后一个空尾块。逐块检查原厂 bit-input CRC，擦行/写页后回读。旧块重传须与已写数据一致才确认；跳块拒绝。
3. 首块写入前清除旧元数据。接收 30 秒无进展则取消 RAM 事务。超时不复位或提交残缺镜像。
4. 完成时通知 `0x15`。`0x16 f2=1` 取消并返回 `0x1a`；其他值尝试提交。提交前验证向量、全镜像 CRC32、原厂多复制页所需的擦除填充。
5. 元数据行 `0x3ff00` 先擦除，先写入并回读 `0x3ff40` 扩展日志，再写并回读基础头部。基础头部为 pending=1 与大端 16 位长度。扩展日志为 `M1UP`、小端长度、CRC32、CRC32 反码、长度反码；剩余字节 `ff`。提交成功后关闭显示，等待 4000 ms，再拉低 PA24，至少保持 1000 ms 后请求系统复位。进入该序列后拒绝新的串口命令，不会因重复提交重启倒计时。原厂 `0x8aae` 有相同的 4000/1000 tick 顺序；原厂没有完整镜像也会进入非取消复位分支，新实现保留提交校验，不复位残缺镜像。MCU 复位会重置 GPIO 方向，不能保证 CHIP_EN 在 Boot 整段期间一直为低；应用初始化重新置高。
6. 新 Boot 校验日志、长度和暂存 CRC 后，按 256 字节擦应用行，按 64 字节写入/回读。全应用 CRC 通过后保留提交日志；下次 Boot 先比较应用 CRC，相同则识别为已完成并直接启动。无需二次编程同一元数据页或擦除完成日志。中断复制仍保留提交记录和暂存，下次重新校验后重做整次复制。
7. Boot 清 SysTick/NVIC pending，设置应用 VTOR/MSP，跳转应用启动；应用重新初始化 `.data/.bss`、外设和时钟。

Flash 驱动按构建角色约束地址：应用只能写暂存与元数据；Boot 额外可以写应用区。两者都没有解除读保护、写 User Row、修改熔丝或自擦 Boot 的能力。升级协议没有读回全部 Flash 的命令。

### 恢复保证的实际范围

主机 Flash 模型要求擦除后每页只编程一次、位变化只允许 1→0，并注入每个读/擦/写操作失败，包含半行擦除与半页写入。已提交事务在搬运中断后能够从暂存重做；提交中断时要么保留旧应用，要么存在可验证的新事务。更细粒度的位损坏、供电跌落、Flash 寿命和真实 NVM 控制器行为还需台架验证，软件模型不能证明所有断电状态。

只有独立新 Boot 会校验扩展日志。原厂 Boot 会忽略扩展日志并按旧规则搬运，不能套用新恢复结论。新 Boot 不接受没有扩展日志的原厂式 pending 记录；首次替换 Boot 应在独立样机、已备份并可 SWD 恢复的条件下验证。

本实现没有 A/B 旧版本回滚、镜像签名/公钥认证或独立串口救援下载器。CRC 不能认证固件来源。有效 pending 但日志/暂存损坏、或无有效应用时，Boot 保留数据并停止跳转；看门狗重入，持续故障需 SWD 恢复。这里的“恢复”指从完整暂存重做中断搬运，不是保证任意故障自动恢复。

CI 可构建并上传独立 MCU OTA 候选包，实际镜像经过 Flash 模型接收/提交/搬运逐字节检查，见 [ota.md](ota.md)。没有自动刷机或发布正式 Release。
