# RTTTL 音乐与 MCU 数据区

v0.9.3 支持一首 RTTTL 单音音乐，通过配套 M1 WebUI「设置 → 通用 → 自定义 RTTTL 音乐」粘贴或选择 `.rtttl` / `.txt`，点击「写入主控」。可读取回编辑框、播放和停止；首页与闹钟定时可选择「已保存的 RTTTL 音乐」。音乐存于 ATSAMD20G18A 内部 Flash，不存 Wi-Fi 配置，重启和正常应用 OTA 后保留。

示例为自行构造的短音阶：`Chime:d=8,o=5,b=120:c,e,g,4c6`。格式为 `名称:默认参数:音符`；默认 d=4、o=6、b=63。支持 c/d/e/f/g/a/b、升半音 `#`（c/d/f/g/a）、休止 p、附点（八度前或后）、音符时值覆盖及八度 4–7；名称 1–32 可打印 ASCII 字符，d=1/2/4/8/16/32，b=25–900。总长度最多 1024 ASCII 字节，最多 256 音符，总时长 ≤180 秒；不支持和弦、音频文件和连续流。格式含义可参考 [ESPHome RTTTL 文档](https://esphome.io/components/rtttl/)，本实现独立编写，不依赖其框架。

播放器按音符切换硬件 PWM，休止时停输出，不阻塞主循环；音符标称频率经整数表和硬件分频取整。一次播放完成或达到指定时限后恢复普通蜂鸣器策略。调试短音可替换音乐；OTA 开始停止音乐并取消上传。因而「停止」不是永久静音开关，污染物告警仍有效。实体屏幕事件由联网模块停止闹钟音乐。延迟调度从当前音符恢复，不补播一串过期音符。

音乐固定使用 50% 占空比，没有可调电源/功放音量接口。不同音高的实际响度可能差别很大：若低音偏小，可提高 RTTTL 的默认八度并同步调整显式音符八度，例如 `Chime:d=8,o=6,b=120:c,e,g,4c7,p,g,e,4c`；这会改变音高，不保证所有音符都更响。不能用 100% 占空比代替音量放大，驱动中它代表持续高电平。实机短音比较与用户反馈见 Wi-Fi 仓库 `docs/validation/m1-rtttl-tones-20261025.md`。

## 数据布局与写入

数据区为 **0x3e000–0x3efff**，两个 2048 字节槽；槽首 64 字节头部，随后最多 1024 字节 RTTTL。应用最多到 0x13ffe，暂存写入限 0x22000–0x320ff，升级元数据 0x3ff00–0x3ffff；编译断言防止重叠。应用 HAL 仅新增该数据区写权限，独立 Boot 不增加数据区写权限；网络升级不更换 Boot。

头部：0–3=`RTT1`，4–7=大端 generation，8–9=大端长度，12–15=大端 CRC32，16–19=CRC 反码，20–23=generation 反码，其余 `ff`。CRC32 为标准反射多项式 `0xedb88320`、初值/终值异或 `ffffffff`。启动时检查两个槽的头部、数据 CRC、RTTTL 格式，选择较新有效 generation。

上传先进入 RAM 缓冲，收到全部数据并通过 CRC、语法和时长检查后，擦除非当前槽、逐页写入/回读数据，最后写入/回读头部提交；旧槽始终不写。30 秒无上传进展自动取消。非法、中断或取消上传不改变当前曲目；存储错误返回失败，重启扫描可能读到旧曲或已完整提交的新曲。该机制经过每个 Flash 操作的失败、半行擦除和半页写入模型检查，不能替代真实掉电测试。只在用户保存时写 Flash，播放、读取和开机不写。

## 串口扩展

请求 `23 70 0f SEQ A0 A1 A2 A3 A4 A5 A6 21`；应答沿用 20 字节 `0x70` 格式。未用参数清零，数值大端。能力 OP00 bit15 表示存储协议；联网模块还检查主控版本 ≥0.9.3、协议 ≥2、PWM 标志和提示音 bit14。

| A0 | 参数 A1–A6 | 成功应答 D0–D13 |
| --- | --- | --- |
| 0 状态 | 全零 | 存在、播放中、长度(2)、CRC(4)、总时长 ms(4)、上传中、存储协议版本1 |
| 1 开始上传 | 长度(2)、CRC32(4) | 清零；正在播放或上传时 busy |
| 2 数据 | 偏移(2)、最多4字节，尾部补零 | 已接收长度(2)；连续接收，同一内容旧块可重传 |
| 3 提交 | 全零 | 清零；必须收齐并校验；存储失败 status4 |
| 4 读取 | 偏移(2)、长度1–10、其余零 | 偏移(2)、长度(1)、最多10数据字节 |
| 5 播放 | 最长秒数(2，1–180)、循环0/1、其余零 | 清零；播放当前已提交曲目 |
| 6 停止 | 全零 | 清零；恢复普通蜂鸣器策略 |
| 7 取消上传 | 全零 | 清零；保留已提交曲目 |

OTA 接收期间所有扩展返回 busy；成功返回表示主控已接受，并不确认实际声音。

## 联网接口

通过鉴权的 `POST /api/v1/command`，也可由 TMCP 转发。均要求版本和能力满足；不要以联网固件版本推断 MCU 能力。

- `music.get {}`：存在/播放/长度/CRC/时长/上传状态与 1024 字节上限。
- `music.begin {"length":35,"crc32":"1234abcd"}`：CRC 是八位十六进制字符串。
- `music.chunk {"offset":0,"data":"Chim"}`：每次 1–4 ASCII 字节，末块按实际长度；相同块重传不重复追加。
- `music.commit {}`、`music.cancel {}`：提交或取消。
- `music.read {"offset":0,"length":10}`：返回 `data` 字符串。
- `music.play {}`：单次播放，最多 180 秒；`music.stop {}` 停止。
- `wake_alarm.start {"duration_seconds":60,"tone":5}`：最长持续 60 秒，曲目结束后循环；到期或停止下发 music stop，不每两秒重启曲目。

WebUI 上传显示进度，数据块网络错误最多重试三次，提交后检查 MCU 长度和 CRC；读取也校验完整文本 CRC。写入失败保留编辑内容并尝试取消上传。已有非零音色的定时任务在降级主控后不会自动改成原蜂鸣声。
