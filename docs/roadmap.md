## 建议的下一批改动

1. 恢复时钟树、RTOS tick 与 UART 配置；先做带超时的裸机底层，避免在驱动未通时引入复杂调度。
2. 完成显示数字与符号段表，以及按键定时状态机。仅有灯组掩码不足以驱动整屏。
3. 接入 SHT 原始读写、两路串口帧流和 RTC；恢复热补偿和预热滤波后再宣称数值兼容。
4. 台架上验证串口核心与网络模块互通，补齐 `0x0c/0x10/0x17/0x19` 等确有用途的消息。
5. 再做参数持久化、自定义阈值和蜂鸣器策略，并明确这是新增行为，避免冒充原厂行为。

## 工程约束

- `platform/link_check.c` 是链接夹具，不是主循环实现；不提供 `.bin` 发布或刷机脚本。
- 当前应用从 `0x4000` 链接，保留原 Boot 和升级区域，并以 16 位升级长度限制收紧可用 Flash。还需验证 Boot 交接的时钟、WDT、NVIC 和栈状态。
- 未确认用途的 PA24 不主动驱动；未知传感器型号不硬编码未验证的配置命令。
- 原始健康标志与采样新鲜度分开设计，驱动层需要超时及恢复状态。
- 保留原厂二进制和设备信息在仓库外；新增分析需注明样本 SHA、地址和证明方式。

在硬件驱动和恢复流程完成之前，公开 CI 通过只代表软件核心/内存布局通过，不代表可以替代原厂固件。
