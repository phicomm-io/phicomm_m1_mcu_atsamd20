# MCU 扩展协议 v2

联网模块通过 SERCOM3 UART（115200、8N1）调用开源 MCU 扩展。原厂 MCU 不支持 `0x70`；普通 `0x01–0x1a` 命令保持兼容。联网模块提供需要网页认证的 HTTP 转发入口，见 [网络升级](network-ota.md)。

v1.0.0 保留既有帧格式和操作码，按用途分为三类。正常设备设置使用正式功能；诊断入口显示只读结果；可能临时覆盖输出的命令放入专家工具并明确提示效果。

| 类别 | OP | 用途 |
| --- | --- | --- |
| 正式功能 | `09`、`0a`、`0b`、`0c`、`0e`、`0f` | 阈值、CO₂ 显示与数据、短音、RTTTL 音乐 |
| 只读诊断 | `00`、`06`、`08`、`0d`、`10` | 能力、健康、显示缓存、CO₂ 状态、原始传感器帧 |
| 专家工具 | `01`、`02`、`03`、`04`、`05`、`07` | PWM、数值/屏幕覆盖、RAM 片段、退出覆盖、PM 模式 |
| 通用显示源 | `11`、`12`、`13` | Wi-Fi 数字/单位段/灯色/租期、两来源选择、状态查询 |

v1 新联网固件将 CO₂ 数值换算、灯色和交替策略放在 Wi-Fi MCU，使用通用显示源；`0a/0c/0d` 保留为兼容入口。通用显示、按钮事件和跨仓库兼容规则集中维护在 [IoTCloud 开发文档](https://phicomm-io.github.io/iotcloud-community-protocols/m1-display/)，机器可读定义与测试向量由 `protocols.lock.json` 固定。

功能可用性以能力应答为准，不能将原厂 11.x / 17.x 与开源版本按大小比较。

## 帧与应答

请求固定 12 字节：`23 70 OP SEQ A0 A1 A2 A3 A4 A5 A6 21`。SEQ 为调用方 0–255 的序号。应答固定 20 字节：`23 70 OP SEQ STATUS D0 ... D13 21`，没有独立校验字节。大于一个字节的数值均为大端，温度为 16 位二进制补码。预留参数和未使用应答字节必须清零。

STATUS：0=已接受/查询成功，1=参数错误，2=OTA 接收中忙，3=不支持，4=外设配置失败，5=传感器缓存代数改变（重新读取）。成功表示运行时接受请求；屏幕实际写入由后续轮询完成，不能当作段已亮的物理确认。Wi-Fi MCU 应按 `70/OP/SEQ` 匹配应答，同时分派正常采样、时间和错误通知，不能把下一帧都视为调试应答。无应答可同序号重发；这是重新执行，不是去重操作，会重新开始租期。升级已提交进入复位阶段时不再应答新命令。

## 指令

| OP | A0–A6 | 结果/行为 |
| --- | --- | --- |
| `00` 能力 | 全零 | D0=协议版本 2，D1–2=操作位图 `ffff`，D3–4=最长租期 10000 ms，D5=硬件 PWM 回调存在标志 |
| `01` PWM 蜂鸣器 | A0–1 Hz；A2 占空比%；A3–4 持续 ms；A5–6=0 | 频率 100–10000，非零占空比 1–100，时长 1–10000；占空比 0 停止。100% 是持续高电平。目标频率有定时器整数分频误差 |
| `02` 屏幕数值 | A0–1 甲醛整数；A2–3 PM；A4–5 有符号温度百分位；A6 湿度整数% | 范围分别 0–9999、0–999、−4000..12500、0–100；进入/续期 10 秒屏幕覆盖，退出原始段模式/全段模式 |
| `03` 显示配置 | A0 亮度；A1 开关；A2 全段；A3–4 租期 ms；A5–6=0 | 亮度 0/25/50/75/100；开关、全段均 0/1；租期 1–10000。保留已经注入的数值，退出原始段模式 |
| `04` RAM 片段 | A0 偏移；A1 长度；A2 起数据 | 偏移 0–28；长度 1–5；不得越过 29 字节，未用数据字节为 0。进入原始段模式，续期 10 秒 |
| `05` 退出 | A0=0 全部 / 1 仅屏幕 / 2 仅 PWM；其他=0 | 恢复正常渲染或蜂鸣器策略，无需重启 |
| `06` 诊断 | 全零 | 返回下表 |
| `07` PM 模式 | A0=0 自动 / 2 四帧预热 / 3 两窗口预热+突变过滤；其他=0 | 清接收片段、预热和突变状态；立即安排请求。模式保存在 RAM，不随调试租期恢复 |
| `08` 读取显示 RAM | A0 偏移；A1 长度 1–12；其他=0 | D0=偏移，D1=长度，D2 起数据；不得超过 29 字节。读取正常 3 秒渲染缓存或当前调试覆盖缓冲区，叠加当前冒号相位及 CO₂ 显示；不是 TM1680 硬件回读 |
| `09` 查询阈值 | 全零 | 读取甲醛/PM 两档当前阈值和功能位，见下文 |
| `0a` CO₂ 显示 | A0 模式 0=不替换、1=完全替换、2=交替；A1 位置 0=甲醛、1=PM；A2–3 周期秒数 1–3600；其他零 | 每个交替阶段持续给定秒数；相同配置重发不重启交替计时 |
| `0b` 扩展阈值 | A0 对象 0=甲醛、1=PM、2=CO₂；A1–2 低档；A3–4 高档；其他零 | 0≤低档≤高档≤65535，影响对应灯色与高档告警；原厂 05/06 继续可用 |
| `0c` CO₂ 读数 | A0–1 ppm；A2 有效 0/1；A3–4 TTL 秒数；其他零 | 有效时 ppm>0，TTL 1–60；到期或无效立即恢复原始显示 |
| `0d` CO₂ 状态 | 全零 | D0 模式、D1 位置、D2–3 周期、D4–5 低档、D6–7 高档、D8–9 ppm、D10 数据有效、D11 当前显示 CO₂、D12–13 剩余 TTL 秒数 |
| `10` 传感器帧 | ID、模式、偏移、长度、代数，见专页 | 分块读取完整传感器响应及其元数据，见 [传感器帧诊断](sensor-frames.md) |
| `0e` 内置短音 | A0 音色 0–4；其余零 | 0 退出 PWM 覆盖；1–4 播放下表单次音。成功时 D0=音色，D1–2=Hz，D3–4=ms，D5=50% |

内置短音自 **v0.9.3** 起提供。联网模块启用选择/试听时须同时检查主控版本 ≥0.9.3、协议 ≥2、能力位 bit14（`0x4000`）及 D5 PWM 标志；旧主控或版本未知时保留原蜂鸣声。这里的 `0x70/0x0e` 不同于普通 `0x0e` 持续开关。

| ID / CLI 名称 | 频率 | 单次持续时间 |
| --- | --- | --- |
| 0 / off | 恢复普通策略 | — |
| 1 / tap | 2000 Hz | 60 ms |
| 2 / confirm | 2500 Hz | 120 ms |
| 3 / notice | 1500 Hz | 250 ms |
| 4 / error | 1000 Hz | 500 ms |

四种音均为 50% 占空比的连续单音，没有音频解码。新音替换当前 PWM 覆盖；非法请求不打断正在播放的音。播放结束、ID 0、退出 PWM 覆盖和 OTA 开始均恢复普通蜂鸣器策略，所以不能用 off 永久关闭污染物告警。时长由主控时间基准执行，不依赖 Wi-Fi 再发停止帧。

`0x70/0x0f` 使用能力位 bit15（`0x8000`）管理一首持久化 RTTTL 音乐。主控 ≥0.9.3、协议/PWM 和 bit15 均通过才能启用 WebUI 音乐功能。子命令、数据分区与异常恢复见 [RTTTL 音乐](music.md)。

CO₂ 小于 1000 时显示整数并关闭小数点；1000–9999 显示为 `1.00`–`9.99`，10000 以上为 `10.0`–`65.5`，后两类按 k ppm 理解。选中位置的原污染物名称与单位段关闭，其他原始数据、UART 查询与温湿度保持原义。玻璃上没有新增 CO₂/k 字样，不能凭数码管判断气体类型。RAM 掩码和小数点位置仍需实物观察确认。

默认模式为不替换，CO₂ 阈值 1000/1500 ppm，交替阶段 5 秒。普通屏幕调试/全段测试优先于 CO₂；CO₂ 数据不会写入甲醛或 PM 样本。该扩展只保存在主控 RAM；联网模块负责持久化配置并在主控重启后同步。

`09` 查询阈值参数全零；D0–1=甲醛低档、D2–3=甲醛高档、D4–5=PM 低档、D6–7=PM 高档，均为大端；D8 功能位 bit0/bit1 表示可配置灯色/高档蜂鸣器告警（当前 `03`），D9–13 清零。写入使用普通 `0x05/0x06`，不是另一个临时覆盖操作；完整规则见 [阈值设置](thresholds.md)。

`06` 诊断数据：

| 字节（D） | 内容 |
| --- | --- |
| D0 / D1 | 当前 PM 模式 / 已跳过的预热帧数 |
| D2 / D3 / D4 | 甲醛 / PM / 温湿度健康字段 |
| D5–6 / D7 | 最近 SHT 状态字 / 当前采集流程状态字是否有效 |
| D8–9 | 成功发出温湿度软复位次数，16 位回绕 |
| D10–11 / D12–13 | RX / TX 错误计数低 16 位 |

SHT 状态位 0/1 为上次写校验/命令失败；4 为复位检测，13 为加热器状态，15 为告警。4/15 单独置位不会触发无限复位。诊断中有效状态查询也不等于有效温湿度样本，应看 D4。

## 示例

发送的是下列十六进制对应的二进制字节，不能直接发送 ASCII 十六进制文本。均使用序号 1：

```text
# 2 kHz、50%、500 ms
23 70 01 01 07 d0 32 01 f4 00 00 21
# 甲醛 301、PM 151、温度 -5.50°C、湿度 55%
23 70 02 01 01 2d 00 97 fd da 37 21
# 50% 亮度、开屏、全段点亮、2000 ms
23 70 03 01 32 01 01 07 d0 00 00 21
# 直接写 RAM[0x13]=0x70（该字节的其余段也会被覆盖）
23 70 04 01 13 01 70 00 00 00 00 21
# 读取 RAM[0x13] 的 1 字节
23 70 08 01 13 01 00 00 00 00 00 21
# 查询诊断 / 退出全部覆盖
23 70 06 01 00 00 00 00 00 00 00 21
23 70 05 01 00 00 00 00 00 00 00 21
```

Wi-Fi MCU 可按下式组帧；UART 发送需在自身已有的串口任务中串行化：

```c
uint8_t request[12] = {0x23, 0x70, 0x01, sequence,
                       0x07, 0xd0, 50, 0x01, 0xf4, 0, 0, 0x21};
/* 经现有 MCU UART 发送 request 的全部 12 字节，等待匹配应答。 */
```

电脑离线组帧，无第三方依赖；该工具只输出字节，不自动访问设备：

```sh
python3 tools/m1_debug.py pwm 2000 50 500
python3 tools/m1_debug.py tone confirm
python3 tools/m1_debug.py tone off
python3 tools/m1_debug.py sample 301 151 -550 55
python3 tools/m1_debug.py display 50 1 1 2000
python3 tools/m1_debug.py raw 0x13 70
python3 tools/m1_debug.py read 0x13 1
python3 tools/m1_debug.py --seq 2 status
python3 tools/m1_debug.py pm-mode 2
python3 tools/m1_debug.py exit
python3 tools/m1_debug.py threshold hcho 80 100
python3 tools/m1_debug.py threshold pm25 35 75
python3 tools/m1_debug.py thresholds
```

## 覆盖与恢复

屏幕调试保留正常采样、健康、RTC、阈值和 `0x01/0x19` 返回值；真实显示开关参与温湿度热补偿。屏幕注入默认沿用进入时的亮度/开关，若屏幕已关需先发 `03`。新 `02/04` 续期为 10 秒；`03` 使用给定租期。每个 RAM 片段在后续刷新时生效，不承诺多个片段一次原子提交。段偏移及颜色见 [hardware.md](hardware.md)。

PWM 覆盖期间正常蜂鸣器策略暂不驱动管脚，结束时恢复 2 kHz/50% 的普通配置及当前普通策略；此前普通 `0x0e` 持续开，则结束后仍可能持续鸣响。开始 OTA `0x12` 自动结束屏幕/PWM 覆盖；OTA 接收期间全部 `0x70` 返回忙。PM 模式选择是独立诊断设置，不属于屏幕/PWM 租期。调试状态不写 Flash。

OP00 另在 D6/D7/D8 返回传感器帧 schema/种类数/最大读取块长度。该能力不占用已满的 OP00–0f 位图，详见 [传感器帧诊断](sensor-frames.md)。

v1 新增 D9=按钮事件 schema 1、D10=事件种类位图 `0f`、D11=通用显示 schema 1、D12=可选蜂鸣报警 schema 1；这些分别是应答帧绝对偏移 14、15、16、17。通用显示 OP `11`–`13` 和报警 OP `14` 不占用旧的 16 位操作码位图。调用前先核对对应能力；旧 MCU 未声明时不能直接发送新操作。

`OP 14` 为可选的传感器超阈值蜂鸣报警读写，默认关闭，不改变色灯阈值。请求、位图与读回格式见[告警阈值](thresholds.md#可选蜂鸣报警)。
